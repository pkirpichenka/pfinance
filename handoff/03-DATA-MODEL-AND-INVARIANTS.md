# 03. Модель данных и финансовые инварианты

## Главный принцип

Банковский счёт — реальный денежный контейнер. Бизнес-точка — аналитическое направление. Один счёт может обслуживать несколько точек, но его остаток нельзя дублировать по каждой точке.

## Счёт

Упрощённая форма:

```js
{
  id,
  name,
  bankName,
  emoji,
  kind,
  currency,
  opening,
  limit,
  archived,
  scope: "personal" | "business",
  legalEntityId,
  businessIds,
  sharedCash?,
  system?
}
```

`limit` участвует только в показателе доступности личных счетов. Фактический баланс считается отдельно.

## Бизнес-точка

```js
{
  id,
  name,
  emoji,
  legalEntityId,
  cashOpening,
  acceptsCash,
  archived,
  technical?
}
```

## Долг

Долг хранит собственную валюту и массив частичных погашений. Движение денег по счёту может быть в другой валюте и фиксируется отдельной фактической суммой.

Внутренние требования к собственному ИП/ООО могут иметь:

```js
kind: "owner_reimbursement"
```

Текущая формула чистого личного капитала:

```text
личные счета + мне должны − я должен
```

Деньги бизнеса в неё не входят.

## Типы операций

Актуальный набор включает как минимум:

- `in` — личный доход;
- `out` — личный расход;
- `draw` — вывод из бизнеса на личный счёт;
- `contribution` — взнос с личного счёта в бизнес;
- `biz_income` — доход бизнеса;
- `biz_expense` — расход бизнеса;
- `transfer` — перевод между допустимыми счетами;
- `entity_transfer` — перемещение между разными юрлицами;
- `cash_transfer` — инкассация между кассой студии и её банковским счётом;
- `personal_biz_expense` — личная оплата за бизнес с распределением по точкам;
- `account_adjustment` — техническая корректировка счёта;
- `biz_adjustment` — корректировка наличного канала точки;
- долговые движения `debt_*`.

## Инварианты

### Разделение денег

- Личные счета не являются счетами бизнеса.
- Деньги бизнеса не входят в сумму «Ваши личные деньги».
- Общая касса трёх студий учитывается один раз.
- Общий счёт ООО учитывается один раз.

### Прибыль и денежный поток

- `transfer`, `entity_transfer`, `cash_transfer` не являются доходом или расходом.
- `account_adjustment` и `biz_adjustment` не должны искажать прибыль.
- `draw` и `contribution` не являются обычным личным доходом/расходом.
- Возмещение личных расходов не должно признаваться повторным доходом или повторным расходом.
- `personal_biz_expense` уменьшает личный счёт и прибыль выбранных точек, но не меняет их банковские счета/кассу в момент оплаты.

### Валюты

- Сумма долга остаётся в исходной валюте.
- Перевод между валютами хранит `amount` и `toAmount` как зафиксированные фактические суммы.
- Агрегаты конвертируются в базовую валюту по сохранённым курсам.
- Изменение текущего курса не должно переписывать исторические фактические движения.

### Сверка остатка

Пользователь вводит фактический остаток; приложение создаёт разницу:

```text
корректировка = фактический остаток − расчётный остаток
```

Техническая корректировка меняет баланс, но не прибыль. Если пользователь выбирает учёт как доход/расход, должна быть указана точка и категория.

### Безопасность удаления

- Объекты с историей не должны удаляться так, чтобы операции потеряли ссылки.
- Для счетов/точек с историей предпочтительно архивирование.
- Undo должен удалять все связанные записи, созданные одной составной операцией.

## Миграции

Все новые поля состояния должны добавляться аддитивно:

- старые значения сохраняются;
- отсутствующие поля получают безопасный default;
- повторный запуск миграции не создаёт дубликатов;
- существующие операции не пересчитываются задним числом без явной необходимости;
- версия модели меняется только при реальном изменении схемы.
