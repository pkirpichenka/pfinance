Безналичная операция меняет банковский счёт соответствующего ИП или ООО. Наличная операция меняет остаток конкретной студии и общий остаток карточки «Наличные».

## Мультивалютные долги

Каждый долг хранит собственную валюту: BYN, USD, EUR, RUB или любую добавленную пользователем.

При создании долга можно отдельно указать:

- сумму и валюту обязательства;
- личный счёт, по которому реально прошли деньги;
- фактическую сумму списания или зачисления по этому счёту.

Например, можно выдать **100 USD**, фактически списав **290 BYN** с BYN-карты. Долг останется равным 100 USD, а баланс карты уменьшится на 290 BYN. Выдача, получение и возврат займов не попадают в личные доходы и расходы.

Общие суммы «Мне должны» и «Я должен» показываются в базовой валюте по текущим курсам, а карточка каждого долга — в его исходной валюте.

## Личная оплата за бизнес

Для сервиса, оплаченного личной картой, используйте операцию **«Личная оплата за бизнес»**.

Она:

1. уменьшает выбранный личный счёт на общую сумму;
2. распределяет расход между выбранными точками поровну или вручную;
3. уменьшает прибыль каждой точки на её долю;
4. не меняет банковские счета бизнеса и общую кассу, потому что деньги ушли с личной карты;
5. при варианте «Бизнес должен вернуть мне» создаёт отдельный долг каждого юрлица перед владельцем.

Пример для Wazzup на три студии при равном распределении:

- Студия Толбухина — 1/3 расхода, долг ИП перед владельцем;
- Студия Куйбышева — 1/3 расхода;
- Студия Машерова — 1/3 расхода;
- долг ООО перед владельцем равен сумме двух долей.

Когда ИП или ООО возвращает деньги:

1. внесите операцию **«Вывод из бизнеса»**;
2. выберите категорию **«Возмещение личных расходов»**;
3. выберите бизнес-счёт и личную карту;
4. затем отметьте соответствующую сумму как погашенную в разделе «Долги».

Такой возврат меняет только остатки счетов и не считается повторным расходом, личным доходом или выводом прибыли.

> Это схема управленческого учёта в приложении. Налоговое и бухгалтерское оформление расходов ООО, оплаченных личной картой, следует согласовать с бухгалтером и подтвердить первичными документами.

## Публикация

Загрузите содержимое папки проекта в корень GitHub-репозитория. Для работы сайта обязательно оставьте `index.html` и `CNAME`.

После commit дождитесь GitHub Pages deployment и обновите страницу без кэша.

## Миграция данных

Новая SQL-миграция не требуется. Приложение продолжает хранить единый JSONB-объект в `public.app_state`.

При первом запуске версии 4.2.0:

- старым долгам без валюты назначается текущая базовая валюта;
- структура ИП, ООО, точек, банковских счетов и общей кассы сохраняется;
- существующие операции не удаляются и не пересчитываются задним числом;
- версия модели данных обновляется до `6`.

Реальные пароли и `service_role`-ключи в комплект не входят. Публичный Supabase anon key остаётся в клиентском HTML; доступ к данным ограничивает RLS.
