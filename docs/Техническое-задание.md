# Техническое задание: личный финансовый дашборд

Документ описывает проект **полностью и однозначно**. Это спецификация к эталонному файлу
`finance-dashboard.html`. Если между этим текстом и файлом возникает расхождение — **истиной считается файл**.

---

## 0. Что это и главный принцип

Одностраничное веб-приложение (SPA) для личного финансового учёта владельца небольшого бизнеса
(3 студии растяжки, кофейный и снековый аппараты). Приложение ведётся вручную, ежедневно, в основном с телефона.

**Главный смысловой принцип, который нельзя нарушать:** деньги делятся на два непересекающихся контура —
**личные деньги** (реально ваши: карты, наличные) и **деньги бизнеса в обороте** (на счетах студий/аппаратов).
Перемещения между контурами (вывод себе / возврат в дело) **не считаются** личным доходом или расходом.

- **Технологии:** один файл `.html`. Внутри: HTML + CSS + чистый JavaScript (без фреймворков, без сборки, без внешних JS-библиотек). Единственная внешняя зависимость — шрифты Google Fonts по `<link>`.
- **Хранение данных:** через `window.storage` (async key-value API среды исполнения) с деградацией в память. Никакого `localStorage`.
- **Язык интерфейса:** русский. Валюта по умолчанию — рубль, базовая валюта настраивается.

## 3. Модель данных (объект состояния `S`)

Всё состояние — один объект `S`, сериализуется в JSON и хранится под ключом `pf:state:v3`.

```js
S = {
  settings: { baseCurrency:"RUB", reminderTime:"20:00", notify:false },
  currencies: [ { code:"RUB", symbol:"₽", rate:1 }, … ],   // rate = сколько базовой валюты стоит 1 единица
  accounts:  [ { id, name, kind, currency, opening, limit, emoji }, … ],
  businesses:[ { id, name, emoji, opening }, … ],
  categories:{ in:[…], out:[…], bizIn:[…], bizOut:[…] },
  tx:    [ … операции … ],
  debts: [ … долги … ],
  goals: [ … цели … ],
  meta:  { lastEntryDate, lastNotifiedDate, created },
  ui:    { view, txFilter, txPeriod }
}
```

### 3.1. Счёт (account)
- `kind`: `"card"` (карта) | `"credit"` (кредитка/овердрафт) | `"cash"` (наличные).
- `currency`: код валюты из `currencies`.
- `opening`: текущий/стартовый баланс в валюте счёта (для кредитки может быть отрицательным — уже потраченная часть кредита).
- `limit`: кредитный лимит/овердрафт (0 — обычная карта или наличные). Баланс может уходить в минус в пределах `-limit`.

### 3.2. Операция (tx)
Поля: `{ id, type, amount, cat, date, note }` + опционально `account`, `biz`.
- `amount` — всегда в валюте счёта (`account`) для личных операций; для операций бизнеса — в базовой валюте.
- `date` — строка `YYYY-MM-DD`.
- `type` — один из шести (см. раздел 4).
- `account` — присутствует у типов `in, out, draw, contribution`.
- `biz` — присутствует у типов `draw, contribution, biz_income, biz_expense`.

### 3.3. Долг (debt)
`{ id, dir, who, amount, date, due, note, repaid:[ { amount, date }, … ] }`
- `dir`: `"in"` (мне должны) | `"out"` (я должен).
- `repaid` — массив частичных возвратов/платежей.

### 3.4. Цель (goal)
`{ id, name, target, saved, due, note }`.

## 4. Типы операций и их влияние (ЯДРО ЛОГИКИ — НЕ МЕНЯТЬ)

| Тип (`type`)     | Название в UI       | Личный счёт (`account`) | Счёт бизнеса (`biz`)         | Смысл |
|------------------|---------------------|--------------------------|------------------------------|-------|
| `in`             | Доход               | **+amount**              | —                            | реальный личный доход |
| `out`            | Расход              | **−amount**              | —                            | реальная личная трата |
| `draw`           | Вывод из бизнеса    | **+amount**              | **−toBase(amount)**          | взял себе; **НЕ доход** |
| `contribution`   | Возврат в бизнес    | **−amount**              | **+toBase(amount)**          | вернул на ЗП/закупки; **НЕ расход** |
| `biz_income`     | Доход бизнеса       | —                        | **+amount** (в базовой)      | выручка на счёт бизнеса |
| `biz_expense`    | Расход бизнеса      | —                        | **−amount** (в базовой)      | оплата со счёта бизнеса |

`toBase(amount)` — конвертация суммы операции из валюты её счёта в базовую валюту (см. раздел 5).

---

## 5. Валюты и конвертация

- Базовая валюта: `S.settings.baseCurrency`. У неё `rate = 1`.
- `rate(code)` — сколько единиц базовой валюты стоит 1 единица валюты `code`.
- `toBase(amount, code) = amount * rate(code)`.
- Все агрегаты и общий итог считаются **в базовой валюте**. Отдельные счета/операции показываются в своей валюте, при отличии от базовой рядом даётся `≈ <сумма в базовой>`.
- Курсы задаются вручную в настройках (живых котировок нет).

Форматирование денег `fmt(n, sign, code)`:
- округление до целого; разделитель разрядов — `Intl.NumberFormat("ru-RU")`;
- отрицательные — со знаком «−» (U+2212); при `sign=true` положительные — со знаком «+»;
- в конце символ валюты (`code`, по умолчанию — базовая).

## 6. Формулы расчётов (ТОЧНО КАК В ФАЙЛЕ)

```
accountBalance(id)   = opening + Σ(in|draw: +amount) + Σ(out|contribution: −amount)   // по операциям этого счёта, в валюте счёта
accUsedCredit(id)    = max(0, −accountBalance(id))                                     // использованный кредит
accAvailable(id)     = accountBalance(id) + limit                                      // доступно к тратам

personalBalance()    = Σ по счетам toBase(accountBalance(id), currency)                // общий личный итог в базовой валюте
totalCreditUsed()    = Σ по счетам toBase(accUsedCredit(id), currency)
totalAvailable()     = Σ по счетам toBase(accAvailable(id), currency)

bizBalance(id)       = opening + Σ(biz_income:+amount) + Σ(biz_expense:−amount)
                              + Σ(draw:−toBase(amount)) + Σ(contribution:+toBase(amount))   // в базовой валюте
bizTotalBalance()    = Σ bizBalance(id)

sumTx(pred)          = Σ по операциям, удовлетворяющим pred, toBase(amount, валюта счёта|базовая)   // всегда в базовой

monthAgg()           = { income, expense, draw, contribution } — суммы за текущий месяц по типам (в базовой)
netDrawMonth()       = draw − contribution (за месяц)                 // «чистый вывод» = реальный доход с бизнеса
realIncomeMonth()    = income + netDrawMonth()                        // реальный личный доход за месяц

debtRemaining(d)     = amount − Σ repaid.amount
owedToMe()           = Σ max(0, debtRemaining) по dir="in"
iOwe()               = Σ max(0, debtRemaining) по dir="out"

bizStats(id)         = { income, expense, draw, contribution, balance }; «чистый доход точки» = draw − contribution
```

### Прогноз
```
monthlySeries()  — последние 6 месяцев: { label, income, expense, net }, net = income + (draw−contribution) − expense (в базовой)
avgMonthlyNet()  — среднее net по месяцам, где были операции
Прогноз баланса: run = personalBalance(); для каждого из следующих 6 месяцев run += avgMonthlyNet() + плановые движения долгов этого месяца (dir="in": +остаток, dir="out": −остаток по дате due)
Цель — прогноз даты достижения: месяцев = ceil((target−saved)/avgMonthlyNet()) при avgMonthlyNet()>0
```

## 7. Навигация и экраны

### 7.1. Разделы (порядок в меню)
1. **Обзор** (`overview`)
2. **Счета** (`accounts`)
3. **Внести операцию** (`add`)
4. **Операции** (`tx`)
5. **Долги и кредиты** (`debts`)
6. **Бизнес** (`business`)
7. **Прогноз** (`forecast`)
8. **Цели** (`goals`)
9. **Настройки** (`settings`)

Роутинг — переключением `S.ui.view` и полной перерисовкой (`render()` заново задаёт `#app.innerHTML`, затем в `#main` вставляется HTML активного экрана). Обработка кликов — делегированием на `document` по атрибутам `data-act` (чтобы работало после перерисовок).

### 7.2. Обзор
- **Баннер-напоминание** сверху, если `meta.lastEntryDate !== сегодня` (кнопка «Внести операцию» и крестик «отложить на сегодня»).
- **Сплит-баланс** (сигнатурный элемент): две панели рядом —
  - «Ваши личные деньги» (зелёная): `personalBalance()`, под ним «доступно с лимитами», «доход/мес», «расходы/мес», «чистый вывод/мес»;
  - «Деньги бизнеса в обороте» (янтарная): `bizTotalBalance()`, «выведено/мес», «возвращено/мес».
- **Полоса счетов** (горизонтальная прокрутка): по каждому счёту баланс, для кредиток — долг/лимит.
- **4 KPI-карточки:** реальный доход за месяц, расходы за месяц, «мне должны», «я должен».
- **График** динамики за 6 месяцев (столбцы доход/расход + подпись net).
- **Ближайшие возвраты** (топ-4 долга по сроку), **прогресс по целям** (топ-3), мини-прогноз баланса.

### 7.3. Счета
- Итог по всем счетам (в базовой), «доступно с лимитами», «долг по кредиткам», подытоги по валютам с курсами.
- Карточки счетов: баланс (в валюте, при инвалюте `≈ база`), тип, для кредиток — полоса «долг/доступно из лимита». Кнопки «изменить»/«удалить» (удаление запрещено, если по счёту есть операции).
- Кнопка «Добавить счёт» → форма (название, значок-эмодзи, тип, валюта, текущий баланс, кредитный лимит).

### 7.4. Внести операцию
- Плитки выбора **типа операции** (6 штук, см. раздел 4).
- Поля: сумма (подпись валюты меняется под выбранный счёт), дата (по умолчанию сегодня).
- **Счёт** — показывается для `in/out/draw/contribution`; подпись зависит от типа («Куда пришло», «С какого счёта», «На какой счёт вывели», «С какого счёта вернули»).
- **Бизнес** — показывается для `draw/contribution/biz_income/biz_expense`.
- **Категория** — список зависит от типа:
  - `in` → `categories.in`; `out` → `categories.out`;
  - `draw` → `["Вывод на карту","Вывод наличными"]`;
  - `biz_income` → `categories.bizIn`; `biz_expense` и `contribution` → `categories.bizOut`.
- Блок-пояснение под формой описывает эффект выбранного типа (что произойдёт с балансами).
- Кнопка «Сохранить операцию»: валидирует сумму > 0, добавляет `tx`, ставит `meta.lastEntryDate = сегодня`, показывает тост, переходит на «Операции».

### 7.5. Операции
- Фильтры по типу (Все/Доходы/Расходы/Выводы/Возвраты/Доход бизнеса/Расход бизнеса) и период (За всё время / Этот месяц).
- Таблица: Дата, Тип (цветной «чип»), Категория/детали (+бизнес, +комментарий), Счёт, Сумма (в валюте, при инвалюте `≈ база`), удаление.
- Пустое состояние с приглашением добавить.

### 7.6. Долги и кредиты
- Две колонки: «Мне должны» (синие) и «Я должен» (красные), с суммами итогов.
- Карточка долга: контрагент, сумма-остаток из общей суммы, срок с подсветкой (сегодня/≤7 дней — янтарный, просрочено — красный), прогресс закрытия, кнопки «Отметить возврат/платёж», «изменить», «удалить».
- Форма долга: направление, кто/название, сумма, дата выдачи, срок возврата, комментарий.
- «Отметить возврат» добавляет запись в `repaid` (не больше остатка).

### 7.7. Бизнес
- Верхняя сводка: всего в обороте, всего выведено, чистый доход с бизнеса (`выведено − возвращено`).
- Карточки точек: значок, баланс на счёте, выручка, расходы бизнеса, выведено себе, возвращено в дело, **«Ваш чистый доход отсюда» = draw − contribution**.
- «Добавить точку» (название, эмодзи, стартовый баланс). Удаление запрещено при наличии операций по точке.

### 7.8. Прогноз
- KPI: баланс через 1/3/6 месяцев, средний поток/мес.
- График-линия прогноза личного баланса на 6 месяцев (с учётом среднего потока и плановых возвратов долгов по срокам).
- Таблица плановых движений по долгам (по дате `due`).
- Явная оговорка, что это оценка.

### 7.9. Цели
- Карточки целей: прогресс-бар, накоплено/цель, остаток, **прогноз даты достижения** при текущем темпе. Кнопки «Отложить в цель», «изменить», «удалить».
- «Новая цель» (название, нужно накопить, уже отложено, срок, комментарий).

### 7.10. Настройки
- **Валюты и курсы:** выбор базовой валюты; список валют с редактируемым курсом; добавление валюты (код, символ, курс); удаление (нельзя базовую и валюту, в которой есть счета).
- **Напоминания:** время; чекбокс браузерных уведомлений; пояснение, что уведомление срабатывает только пока приложение открыто.
- **Категории:** доходов, расходов, доходов бизнеса, расходов бизнеса — добавление/удаление «чипами».
- **Данные:** экспорт резервной копии `.json`, импорт из `.json`, «Начать с чистого листа» (обнуляет операции/долги/цели и балансы, опционально сохраняет структуру: счета, точки, валюты, категории).

## 8. Мобильная адаптация (основной сценарий — телефон)

Три состояния по ширине:
- **Десктоп (>900px):** левый сайдбар с навигацией.
- **Планшет (≤900px):** сайдбар сохраняется; контент-сетки схлопываются в одну колонку, KPI по 2 в ряд.
- **Телефон (≤640px):**
  - сайдбар скрыт; сверху **компактная шапка** (значок, название текущего раздела, кнопка «Внести»);
  - снизу **фиксированная навигация**: Обзор · Счета · крупная центральная кнопка **＋ Внести** (приподнята) · Долги · **Ещё**;
  - «Ещё» открывает **нижнюю шторку** со списком: Операции, Бизнес, Прогноз, Цели, Настройки;
  - **таблицы превращаются в карточки** (через `data-label` на ячейках и CSS: `thead` скрыт, `td` — flex с подписью из `::before`);
  - **модалки/формы выезжают снизу** как шторка на всю ширину; кнопки растянуты;
  - поля ввода — `font-size:16px` (чтобы iOS не зумил);
  - учтены безопасные зоны iPhone (`env(safe-area-inset-*)`), тосты подняты над нижней навигацией.

## 9. Хранение, миграции, служебное

- **Ключ хранилища:** `pf:state:v3`.
- **Загрузка:** `window.storage.get(KEY)` → `JSON.parse`. При отсутствии/недоступности — деградация в `window.__mem`, затем — стартовые демо-данные `seed()`.
- **Сохранение:** дебаунс ~120мс; в `window.__mem` всегда, в `window.storage.set` — если доступно. Всё обёрнуто в try/catch.
- **Миграции при загрузке (обязательны для старых сохранений):**
  1. Если нет `categories.bizIn/bizOut`, но есть старый `categories.biz` — разделить: доходные (по маске «выруч|доход») → `bizIn`, остальные → `bizOut`; удалить `categories.biz`.
  2. Если нет `currencies` — создать `[{code:"RUB", symbol: старый settings.currency || "₽", rate:1}]`, задать `settings.baseCurrency="RUB"`.
  3. Если нет `accounts` — создать один счёт «Основной счёт» (валюта = базовая, `opening` = старый `settings.openingPersonal||0`) и привязать к нему все прежние личные операции (`in/out/draw/contribution` без `account`).
- **Напоминания:** `setInterval` раз в 60с; если `notify` включено, сейчас ≥ `reminderTime`, за сегодня ещё не уведомляли и нет записей — показать браузерное `Notification` (или тост как запасной вариант), пометить `meta.lastNotifiedDate`.

- `out`: Продукты, Кафе и рестораны, Транспорт, Аренда жилья, Коммуналка, Здоровье, Одежда, Развлечения, Путешествия, Прочее.
- `bizIn`: Выручка, Прочий доход бизнеса.
- `bizOut`: ЗП тренерам, ЗП администраторам, Аренда помещения, Закупка товара, Обслуживание аппарата, Реклама, Ремонт / инвентарь, Прочее.

**Операции, долги, цели** — как в файле (даты задаются относительно сегодня функциями `daysAgo/daysAhead`, чтобы демо всегда было «свежим»). Точный список — в `finance-dashboard.html`, функция `seed()`.

## 11. Графики

Рисуются вручную как SVG (без библиотек), масштабируются через `viewBox` + `width:100%`:
