# Отчёт проверки PFinance 4.5.5

Дата: 27 июля 2026 года.

## Объём изменения

Добавлен сценарий сверки расчётного и фактического остатка на карточках счетов. Пользователь вводит текущий остаток, а приложение автоматически формирует операцию на разницу.

Формулы существующих типов операций, расчёты балансов, долгов, прибыли, общей кассы и структура хранения в Supabase не изменялись.

## Проверенные сценарии

### Личный счёт — техническая корректировка

- Расчётный остаток: 20,00 Br.
- Фактический остаток: 120,00 Br.
- Создаётся `account_adjustment` с `delta = +100,00`.
- Итоговый остаток счёта становится 120,00 Br.
- Доходы и расходы не изменяются.

### Банковский счёт бизнеса — учесть как доход

- Расчётный остаток: 50,00 Br.
- Фактический остаток: 250,00 Br.
- При выборе связанной точки создаётся `biz_income` на 200,00 Br.
- Итоговый банковский остаток становится 250,00 Br.
- Доход относится к выбранной точке и категории.

### Общая касса — техническая сверка

- Фактическая разница 300,00 Br распределена по трём студиям по 100,00 Br.
- Создаются три операции `biz_adjustment`.
- Общая касса увеличивается на 300,00 Br.
- Наличные каналы студий увеличиваются на соответствующие доли.
- `reconcile()` не обнаруживает расхождений.

### Общая касса — учесть как расход

- Отрицательная разница 150,00 Br распределена по трём студиям по 50,00 Br.
- Создаются три операции `biz_expense` с методом оплаты `cash`.
- Общая касса и наличные остатки студий уменьшаются суммарно на 150,00 Br.
- Расход включается в показатели выбранных студий.

### Валидация и отмена

- Нулевая разница не сохраняется.
- Для банковского счёта бизнеса в режиме дохода/расхода требуется связанная точка.
- Для общей кассы сумма распределения обязана совпадать с абсолютной величиной разницы с допуском 0,01 Br.
- Пятисекундная отмена удаляет все записи, созданные одной сверкой.
